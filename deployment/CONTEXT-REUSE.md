# Wiki 回用：从项目问题到可引用的决定

目标是让 Agent 在处理项目问题前获得相关决定、理由、适用条件和证据，并能按需补查。写入成功、维护检查通过或 hook 进程退出成功，都不能证明知识已被 Agent 采用。

## 读写分开

`UserPromptSubmit` 分别计算只读项目范围和写入资格。只读范围可以来自受信仓库、精确项目路径、明确业务别名或已有任务绑定，不再要求长追问包含采集关键词。共享别名仍须区分平台；不同项目或平台冲突、第三方仓库、排除路径和普通闲聊不会被猜成业务范围。没有独立项目路径或别名的明确 Wiki 运维问题不会继承旧业务绑定，并清空该绑定，防止 compact/resume 重放旧业务决定。写入继续使用原有证据与路由规则，`readProjectId` 不会赋予采集资格。

安装升级对 `topicTerms` 合并模板与本机扩展词，保留本机路径、映射和角色。`requiredTerms` 仍由模板定义平台边界；已不再需要的本机扩展词应显式从本机配置删除。

## 共享检索服务

原生 hook 与 MCP `get_project_context` 共用 `buildTaskContext`：

1. 固定当前副本目录，先按项目和允许页面集合限缩范围，再进行检索。
2. 先判断相关性，再融合词面与语义排名。中文分词、英文整词匹配避免把 `CI` 命中到 `precision` 等无关词中；页面标题、决策对象和适用范围不能单独使章节入选，章节自身需要匹配。词面需要覆盖足够的查询词，弱语义邻居不能仅凭“排第一”自动注入。通过过滤的两路用 RRF（按排名倒数合并）融合，避免把词面分数与余弦分数直接相加。语义不可用时保留词面结果，并返回降级原因。
3. 从当前页面选择完整决定段落，连同前言及同页“适用范围/适用条件/目标与状态/适用边界”段落和引用。英文对应 `scope`、`applicability`。这些限定放在 `qualifications`；段落自身仍须有引用，不能借用范围引用为无来源的结论背书。拒绝 stale、archived、contradicted 页面及无法核实引用的决定。
4. 返回页面 ID、完整页面内容版本、页面更新时间、决策对象与相应来源。`temporalStatus` 只来自页面/章节的显式标记；明确询问现行规则时排除历史章节，询问历史时仍先按相关性排序，仅同分时优先历史章节，混合问题保留两者。页面更新时间不是证据发生或决定生效时间，`current` 也不证明实现已生效；正文中的日期、适用条件和历史限定必须保留。

每次最多选择 3 页、6 个段落，证据对象合计不超过 16,000 字符。`complete` 只表示命中的段落是否全部展开，不保证答案充分或结论仍适用于现在。未命中任何段落时，返回本项目最多 12 个当前可用主题页 ID 供补查，不将它们标为已命中证据。超限时保留页面指针并要求补查，不裁掉决定后半段的限定条件。

启用 `topicScope: semantic` 时，hook 与 MCP `get_knowledge_context` 沿用同一个服务跨来源项目检索；相关的跨项目原则可以复用，返回结果保留来源项目。全库无命中时只给当前项目的补查页；没有当前项目则不给任意全库页面。该规则不把跨项目复用重新变成项目隔离。

目前词面覆盖门槛为加权查询词的 30%，并保留同轮最好词面分数的一半以上；纯语义入选需余弦相似度至少 0.8。满足词面条件的候选可由至少 0.5 的语义分数参与融合。这些是保守的检索启发式，不是置信概率；不同 embedding 模型和中文同义改写仍可能漏召回，应通过下面的场景报告与真实任务观察判断，不能仅为增加非空率放宽门槛。

MCP 使用例：先用 `list_knowledge_projects` 核实项目 ID，再调用：

```json
{"projectId":"game-demo","prompt":"这个小游戏更新时应怎样保留玩家存档？"}
```

问题换向、资料冲突、输出未完整展开或需要核实现状时，Agent 应使用 `get_project_context`，并用 `read_page` 阅读返回 ID 对应的完整主题页。项目未知时返回无命中；不会自动扩大为全库查询。新工具是增量接口，原有 `get_context_pack`、`search_pages`、`read_page` 保留兼容。 完整页补查沿用 `read_page` 现有的 concepts/queries 范围；其他 typed profile 页面不在本轮 hook allowlist 与端到端验收范围。

## 原生 hooks 与上下文寿命

- 输出默认上限 2,400 字符，Python 和 TypeScript 均强制上限 6,000。预算不足时给出补查指针，不写入尚未输出段落的缓存。
- 检索子进程的 4 秒预算包含进程退出。`context` 操作完成检索及试用账本结算、完整写出 JSON 后退出，避免中止后的 HTTP 资源滞留丢弃已经可用的规则回退；其他 worker 操作保持自然退出。
- 最相关的决定每次完整刷新。辅助段落按页面、段落和页面版本去重，问题变化或页面变化会重新选择。
- Prompt 仅记录 `preparedRead`；其 `references` 只包含实际完整展开段落的页面版本和引用，不包含补查指针、重复段落摘要或被裁切的文本。同一 turn 的 Stop 可推进完整输出的回合缓存并清理临时引用。此动作不构成宿主已交付或模型已采用的证明。
- `SessionStart` 的 `compact`、`resume` 清空旧缓存，并按最后一个安全的项目问题重新检索；`clear` 清除任务绑定与缓存。它们不依赖 `turn_id` 或对 transcript 路径的猜测。
- 安装器为 Prompt 与上述 SessionStart 设置 `additionalContextLimit: 0`。Codex 的该字段是 token 转存阈值，0 表示不转存；内容上限由本项目负责。[Codex hooks 说明](https://developers.openai.com/codex/hooks)

明确询问 Wiki 运维时，最多加入 1,000 字符的当前快照。共享目录可见的合法 ownership 回执不代表本机已采用；回执缺失或验证失败显示未知。回执不会仅因 mtime 变旧而失效。维护/副本快照另标观测时间和历史状态。

## 可观测性与验收

私有 `context-diagnostics` 按 session + turn 的 hash 记录，避免后续问题覆盖前一回合的观察；记录项目、路由原因、查询 hash、实际准备证据数、complete、结果状态和降级原因，不存查询或回答正文及引用原文。与私有 turn/session 一样保留 7 天。生命周期回放单列，不进入回合分母；升级前的无 turn 记录也不冒充新数据。

Stop 仅观察同一回合 `last_assistant_message` 是否含准确引用标记或完整页面 ID；缺失 Stop、缺失回答或无法完整观察均保留未知。维护摘要分别统计准备了证据的回合、对应 Stop、明确引用和未知观察，重复 Stop 不重复计数。这不是语义采用率，未显式引用也不等于没使用；事件文本也不是宿主原生交付的证明，`delivery` 与 `adoption` 仍为 `unverified`。

验收分三层：

| 层次 | 需要的证据 |
| --- | --- |
| 服务与适配器 | 真实页面及来源；答案包含目标决定与限定；跨项目内容被排除；故障有可见降级；换问、更新、compact/resume 可重新取得决定 |
| 原生交付 | 新命令在 Codex 原生 hooks UI 已审阅并信任；真实任务 trace 中 hook context/`hookPrompt` 包含预期决定和引用 |
| 实际回用 | 真实回答采用对应决定、正确引用，并区分历史证据和当前验证；仅输出非空不算通过 |

维护原有路由检查与空范围检查不替代答案验收。发布验收应另选 10–20 个真实问题，覆盖不同项目、同页不同决定、长追问、平台歧义、中文降级、状态查询及无命中，并记录期望决定和禁止出现的过期说明。

离线回归通过 `npm run eval:reuse -- /absolute/path/report.json` 执行。它在临时 Wiki 中构建真实页面、来源和状态，直接调用上述 task/hook 入口；不配置 embedding 索引、不调用生成模型、不读取业务会话。固定语料覆盖 34 个中文问题、两种检索范围和后续材料追加。报告逐项保留漏掉的目标、额外章节、明确禁止的跨主题内容，以及实际展开字符数；额外的相关章节不等同于错误知识。

冻结基线在 `test/fixtures/decision-reuse-baseline.json`，对应 `32e20b1815160002e93194d008893c3bed5f4e5f` 的生产代码。无证据问题、明确禁入内容、跨项目原则及追加材料后保留历史原因是自动回归约束；精确章节集合与全部目标召回继续如实报告，不能把仍有漏召回的报告叫“34 项答案全对”。这些合成场景检查检索行为，不能证明真实模型正确整理或采用知识。

## 升级与恢复

从已审查完整 commit 构建运行包，核验 manifest，执行安装 dry-run，保留两机现有私有配置、预算、发布角色及写入协议。此改动不改变 publication、主题页或共享 writer 协议格式，不需要再次迁移 Wiki。

整理策略更新会改变模型调用的冻结输入身份。升级前检查是否有中途批次；若旧批次恢复时报告 `frozen consolidation inputs changed; needs review`，保留原始证据、缓存及待审现场，走现有受审重试流程，不批量清空状态以强行通过。

安装后审阅并信任新增/变化的原生 hooks 命令，重新连接 MCP 以发现新工具；不得把构建完成标记为已安装或已信任。先验证当前运行 commit、读取结果与 native trace，再宣称原生回用已生效。需要回退时使用安装器切回先前经过校验的运行目录，并重新核对原生 hooks 信任；保留诊断现场。
